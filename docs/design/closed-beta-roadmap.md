# Closed beta roadmap

Source design: the topic files in docs/design/ (start at overview.md) and docs/vision/.

Milestones, used the same way in every design record: **alpha** is the first closed beta release (this PR stack); **beta** is added during the closed beta; **after** comes after the closed beta; **someday** has no plan.

## Decided

- Shape: a stack of self contained PRs on top of the agent harness and test review stack. Each PR ends in a simple but realistic Paper demo, informed by the legacy BasicExtension (a showcase, not a full port), with tests. Lower PRs get built while higher ones are still being designed and planned.
- Goal of the full stack: a few entries demo every primitive and the core functions (scenes, audiences, commands, dialogue, events, ...).
- 2026-10-30 additions: interaction bounds; debug and inspect (late, before migrations); a conversion track for legacy extensions starting around layer 20 (WorldGuard is not converted; the region extension from #522 replaces it).
- Scope includes items not yet designed: configurations (root resource replacing configs and snippets), artifacts and assets, and core needs revealed by develop PRs (#521 visibility, #522 region, road network).

- Workflow (2026-11-01): two tracks run side by side. The rough design track (planning phase 2) works bottom up through every layer, M1 first, then M2: an audit lists contradictions, implicit gaps, and pieces that fail the coding principles; each finding is settled one topic at a time or left Open on purpose. The detailed plan track (planning phase 3) plans one layer once the layer below it is built, so planning sees the complete rough picture. The coordinating design thread runs the rough design track; each layer's detailed plan, build, and merge run in their own thread, and their results are reconciled back into these records before the next step.
- Layer 0 (base) is the agent harness and test review stack: #542 (xtask toolchain, two test tiers, worktree stack, generated setup builders, panel integration harness, TestRun results), #543 (secrets), #546 (composable test kits, full stack panel scenarios, full CI tier, idempotent Realm commits with resend). It adds no engine or Paper runtime; layer 1 starts from the current realm and engine code.

- Design contradictions are settled by the first layer that needs them, before that layer is built:

  - a lasting place in authored content, settled 2026-11-04: `BoundPath` becomes an identity and replaces `ItemRef`; layer 7 builds `value_location` because timed reactions are its first stored use. Its cost is about 31 Kotlin, 13 Dart, and 3 Rust exhaustive matches (panel-engine-communication.md).

  - how the realm delivers stored only handlers and derives, settled 2026-11-04: a pending row per reader and key, written in the commit and cleared in the reader's transaction; steps can merge ([stored-data.md](stored-data.md#offline-changes)): layer 6 (stored data).
